# 本站日期与每日高亮整改设计

## 目标

建立一个读者容易理解、自动任务无法随意篡改的时间标准：目录以本站实际发布或实质更新日期为主，原始资料日期只在文章详情页作为补充；每日高亮只代表当天真实新增或真实更新的内容。

## 日期规则

### 目录与首页

- 新文章第一次公开到本站时，显示 `本站发布：YYYY-MM-DD`。
- 已有文章后来确实增加新来源、新事实、新数据或修正结论时，显示 `本站更新：YYYY-MM-DD`。
- 只修改排版、标点、标题、日期字段、链接状态或同义表达，不改变本站日期。
- 首页、今日必读和各专栏目录不再显示 `资料发布日期待核`。

### 文章详情页

- 显示 `本站首次发布：YYYY-MM-DD`。
- 发生实质更新后，同时显示 `本站最后更新：YYYY-MM-DD`。
- 原始资料能够从原文页面或正式元数据核准时，显示 `原文发布：YYYY-MM-DD`。
- 原始资料日期无法核准时，隐藏该字段；不显示“待核”，也不猜测日期。
- 多来源文章在来源清单中分别保存每条原文的日期；目录日期仍以本站时间为准。

### 旧文章回溯

- 优先从 Git 首次出现记录和每日归档确定本站首次发布日期。
- Git 与归档都无法证明具体日期时，使用能够证明的最早本站版本日期，并在后台台账记录证据类型；不在公开页面展示“待核”。
- 禁止因为当天重新构建或重新发布整站而批量改成当天日期。

## 高亮规则

每天生成页面前先清除上一日全部高亮，再根据当天通过审核的审计记录重新生成。

### 可以高亮

- `今日新增`：当天首次公开到本站的新文章、新主题或新课程。
- `今日更新`：已有文章当天增加了新的可靠来源、新事实、新数据、新机制、新例子、新应用方法，或依据新证据修正了结论。

### 不得高亮

- 重新总结旧资料，但没有增加新的信息。
- 只复查来源链接是否可访问。
- 只改排版、标题、措辞、标点、日期或样式。
- 只重新构建、部署或移动文件。
- 只在审计文件中手工声明 `updated`，但正文没有可验证差异。

## 自动判定与数据流

1. 每日更新开始前保存文章正文基线和日期台账。
2. 内容完成后，对每篇候选文章比较更新前后的正文与来源清单。
3. 审计记录必须包含目标文章、变更类型、具体变化、新增或变更来源、更新前后内容摘要和来源核验结果。
4. 高亮程序同时检查审计记录和实际文件差异；两者不一致时拒绝高亮并阻止发布。
5. 日期程序只允许通过“首次发布”或“实质更新”事件修改本站日期。
6. 发布后保存当日台账，为下一次更新提供基线。

## 当前错误数据整改

- 清除现有页面上的全部每日高亮。
- 以最近一次公开版本为基线重新核对当天变更；无法证明是当天新增或实质更新的文章不恢复高亮。
- 把目录中的 `资料发布` 和 `资料发布日期待核` 改成本站日期字段。
- 文章详情页保留已核准的原文日期；无法核准的原文日期字段直接隐藏。

## 测试与验收

- 新文章能够显示 `今日新增` 和正确的本站发布日期。
- 有新事实或新来源的旧文章能够显示 `今日更新`，并更新本站最后更新日期。
- 只改排版、日期、链接状态或同义表达时，高亮程序必须拒绝。
- 审计声明与正文差异不一致时，发布必须失败，页面不得部分写入。
- 第二天运行时，前一天高亮全部消失，只显示新的当天结果。
- 首页、今日必读、十一项专栏目录和文章详情页日期一致。
- 公开页面不再出现 `资料发布日期待核`。
- 390px 手机和1440px电脑页面无横向溢出，日期与标签不遮挡标题。
- 完成后检查内部链接、GitHub Pages公开网址和手机推送回执。

## 不在本次范围内

- 不改变网站地址、站点名称、专栏数量和文章内容结构。
- 不为了达到更新率而批量改写旧文章。
- 不把原文日期重新作为目录的主时间标准。
