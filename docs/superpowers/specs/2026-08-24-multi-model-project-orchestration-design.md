# 自学总站多模型任务协作设计

## 目标

把 `D:\CodexProjects\codex自学习` 登记为自学总站唯一正式 Codex 项目，在该项目下建立一个总控任务和四个分工任务。用户只需要与总控任务沟通，总控负责调度、验收、发布和汇报。

本次不迁移或删除 `%CODEX_HOME%` 下的任务历史、插件、凭据或运行组件。已核对的 C 盘旧项目目录不存在，因此不存在需要搬往 D 盘的第二份网站代码。

## 任务结构

### 1. 自学总站｜总控与发布

- 模型：`gpt-5.6-sol`
- 推理强度：`high`
- 运行位置：D 盘正式项目的主工作目录。
- 职责：读取每日规则、拆分工作、向分工任务派发资料包、汇总结果、最终事实复核、更新主仓库、运行全部测试、提交、推送、验证正式网址并发出手机完工汇报。
- 权限：唯一允许直接向 `main` 提交和发布的任务。

### 2. 自学总站｜来源扫描

- 模型：`gpt-5.6-luna`
- 推理强度：`medium`
- 运行位置：D 盘正式项目的共享工作目录；按任务策略只读交付。
- 职责：依次扫描第一、第二、第三资源库，记录候选信息、原始链接、发布日期、来源等级、适用专栏和重复情况。
- 边界：只发现和整理候选资料，不写网站正文，不提交，不发布。第三资源库只能发现线索。

### 3. 自学总站｜内容撰写

- 模型：`gpt-5.6-terra`
- 推理强度：`medium`
- 运行位置：D 盘正式项目的共享工作目录；按任务策略只读交付。
- 职责：仅根据总控提供的已核验资料包，生成适合初学者阅读的文章初稿，讲清原始资料、背景、关键数据、影响、例子和局限。
- 边界：不得自行增加资料包外事实，不修改正式网站，不提交，不发布。

### 4. 自学总站｜事实复核

- 模型：`gpt-5.6-sol`
- 推理强度：`high`
- 运行位置：D 盘正式项目的共享工作目录；按任务策略只读交付。
- 职责：核对原始来源、日期、数据、因果关系、重要结论和审计资格；输出通过、退回或需进一步核验的逐篇意见。
- 边界：只负责审核，不修改正式网站，不提交，不发布。

### 5. 自学总站｜网站工程

- 模型：`gpt-5.6-terra`
- 推理强度：`high`
- 运行位置：D 盘正式项目的共享工作目录；按任务策略只读交付。
- 职责：根据已通过复核的文章包检查栏目排序、当日高亮、日期台账、归档、构建和布局方案，并向总控交付拟修改文件、补丁说明与测试清单。
- 边界：不直接修改正式网站，不提交，不得绕过总控向 `main` 推送或发布。

## 每日数据流

1. 总控读取 `docs/operations/daily-update.md`、上一日审计、日期台账和更新前基线。
2. 总控派发来源扫描任务。
3. 来源扫描返回候选资料；总控先完成来源分级和必要核验。
4. 总控把只含已核验事实的资料包交给内容撰写任务。
5. 初稿交给事实复核任务；不合格内容退回一次，仍不合格则由总控接管或放弃。
6. 已通过内容交给网站工程任务处理网站变更和测试。
7. 总控在主工作目录复核差异、审计、高亮、日期、链接和布局后，独立完成提交、推送、GitHub Pages验证和手机汇报。

## 并发与冲突控制

- 当前最多同时运行四个任务，包括总控，因此每日工作分两批调度。
- 第一批：总控、来源扫描、内容撰写、事实复核。
- 第二批：总控、网站工程，必要时让复核任务处理返工。
- 分工任务共享 D 盘工作目录，但只能以任务回复交付，不得编辑主工作目录。
- 当前任务工具不能提供单任务操作系统级只读沙箱；`publishAllowed=false` 是调度规则，不是文件系统权限。总控在每次派工前后比较分支、`HEAD`、索引以及全部已跟踪和未跟踪文件的内容哈希，发现越权变化立即停止批次。
- 只有总控拥有流程上的正式发布权，避免多个模型同时修改 `main`、日期台账或网站内容。

## 任务间交付格式

每份交付至少包含：

- 日期和任务批次；
- 文章目标与专栏；
- 原始来源、来源等级和可核准日期；
- 已确认事实与仍不确定内容；
- 变更摘要；
- 是否允许进入下一阶段；
- 需要总控处理的问题。

来源扫描结果、初稿和复核报告均为中间产物，不能因为生成完成就算作网站更新。只有进入正式正文、通过基线比较和审计测试的内容，才计入当日真实更新。

## D 盘项目登记与 C 盘边界

1. 在 Codex 中把 `D:\CodexProjects\codex自学习` 登记为正式本地 Git 项目。
2. 在该项目下创建上述五个可见任务，并固定对应模型和推理强度。
3. 含内部任务 ID 的登记表仅保存在 D 盘私有缓存目录，不提交到公开 GitHub 仓库。
4. 新总控完成项目规则、自动化和发布流程验证后，旧任务仅作历史参考并归档。
5. 不手工移动当前旧任务的会话文件；该文件属于 Codex 任务历史，不是项目代码。
6. 不单独移动 `.codex` 下的插件、运行组件、凭据、缓存或任务数据库。
7. 如果后续确实需要释放 C 盘上的 Codex 运行空间，必须另做一次完整盘点、备份、迁移设计和恢复测试，不与本次项目拆分混合执行。

## 自动化

- 每日自动化最终绑定到新的总控任务和 D 盘正式项目。
- 总控在每日运行中按阶段向现有分工任务发送工作，不为每天更新重复新建任务。
- 任何分工任务失败时，总控记录失败并按职责接管；不能为了凑更新数量降低来源和内容标准。
- 自动化迁移完成并通过一次人工试运行后，才停止旧任务上的每日自动化，避免出现重复发布或漏跑。

## 验收标准

- D 盘目录在 Codex 项目列表中可见，并被识别为 Git 仓库。
- 五个任务在侧边栏中可见，名称、模型、推理强度和职责正确。
- 分工任务不能直接发布，总控能够向它们派发任务并读取结果。
- 完成一次不发布的协作演练，验证来源扫描、初稿、复核、网站工程和总控汇总链路。
- 完成一次正式每日更新，网站测试、GitHub Pages和手机回执全部按原规则执行。
- 旧自动化只有在新链路成功后才停用。
- C 盘不保留重复的网站工作目录；Codex系统数据没有被误搬、误删或破坏。

## 不在本次范围内

- 迁移整个 Codex Home 到 D 盘。
- 删除历史任务或会话记录。
- 建立新的公开网站、GitHub仓库或网址。
- 让本地模型绕过来源核验、事实复核或总控直接发布。
