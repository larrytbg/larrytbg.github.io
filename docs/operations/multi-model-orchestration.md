# 自学总站多模型协作运行规则

## 固定任务

每天复用私有登记表 `D:\CodexCache\self-learning-orchestration\task-orchestration.json` 中登记的一个总控任务和四个工作任务。登记表包含内部任务标识，不得提交到公开仓库。不得为了每日更新重复新建任务，也不得用临时任务替代已登记角色。

模型分工：

- 总控与发布：GPT-5.6 Sol High；
- 来源扫描：GPT-5.6 Luna Medium；
- 内容撰写：GPT-5.6 Terra Medium；
- 事实复核：GPT-5.6 Sol High；
- 网站工程：GPT-5.6 Terra High。

## 唯一发布权

只有总控可以修改主项目、提交 `main`、推送和发布。四个工作任务共享 D 盘项目目录，但当前 Codex 任务工具不能为单个任务提供操作系统级只读沙箱。因此这里的“只读”是明确的任务策略边界，不是文件系统硬隔离：工作任务不得切换 Git 分支、不得写入 `site`、`data`、`docs` 或 `scripts`、不得提交或发布，只能通过任务回复交付结果。

总控不得在工作任务运行期间修改仓库。每次派工前必须执行完整仓库指纹捕获，工作任务返回后立即验证分支、`HEAD`、索引树、全部已跟踪文件内容哈希、未跟踪文件清单及其内容哈希。验证失败就立即停止该批次，先查明并处理差异，不得继续集成或发布。登记表中的 `publishAllowed=false` 是调度政策，不得解释成系统已经撤销了任务的写盘能力。

```powershell
node scripts/capture-repo-guard.mjs --out "D:\CodexCache\self-learning-orchestration\guards\YYYY-MM-DD-BATCH-ROLE.json"
# 工作任务返回后
node scripts/verify-repo-guard.mjs --baseline "D:\CodexCache\self-learning-orchestration\guards\YYYY-MM-DD-BATCH-ROLE.json"
```

网站工程任务也不直接修改网站，只返回拟修改文件、补丁说明、测试命令和检查结果；正式集成由总控执行。这一边界用于避免共享目录中的并发写入和分支冲突。

## 每日派工顺序

1. 总控完成归档、基线和当日任务拆分。
2. 总控向来源扫描任务发送检索范围、时间窗、专栏缺口和交付格式。
3. 总控核验来源候选后，把只含已核验事实的资料包交给内容撰写任务。
4. 每个工作任务返回后，总控核对 `HEAD` 与工作树没有越权变化。
5. 总控把资料包与初稿一起交给事实复核任务。
6. 复核通过的内容交给网站工程任务进行集成方案和测试清单检查。
7. 总控在 D 盘主项目中实施正式变更、生成审计、运行测试、提交、推送、部署并验证。

当前最多同时运行四个任务，包括总控。第一批优先运行总控、来源扫描、内容撰写和事实复核；网站工程在前一批有任务结束后启动。

## 交付字段

每个任务回复必须包含：

- 日期、批次和角色；
- 文章目标和适用专栏；
- 原始来源、来源等级及能核准的发布日期；
- 已确认事实和仍不确定内容；
- 本轮实际完成内容；
- 是否允许进入下一阶段；
- 需要总控处理的问题。

工作任务不得手工填写或猜测自己的任务 ID；任务身份由总控依据私有登记表和实际任务元数据记录，避免正文误填 ID。

中间产物不计入网站更新率。只有总控实际写入正文、通过基线比较并进入当日审计的真实变化才算更新。

## 返工和失败

- 初稿或复核最多退回一次；仍不合格时由总控接管或放弃。
- 工作任务超时、断网或不可用时，总控保留检查点并接管，不得降低来源和内容标准。
- 任何工作任务发生越权写入时，总控立即停止该批次，检查 Git 差异并恢复干净状态后再继续。
- 审计、测试、部署或公网验证失败时，不发布半成品。

## 手机汇报

完成发布后，总控向私有登记表中登记的手机推送任务发送简短完工汇报。只有收到服务端 `status=accepted` 回执才记录为送达。
